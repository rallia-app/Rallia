### 5. Programmatic city pages

`/[locale]/tennis/[city]` + `/[locale]/pickleball/[city]` driven by the Supabase facility/court data.

- [ ] Pick the cities — Montréal, Québec City, Ottawa, Toronto first
- [ ] Decide on slug convention (`/tennis/montreal` vs `/tennis/montreal-qc`)
- [ ] Build the route with:
  - Hero with city name + sport + live count of open games this week (from `search_public_matches` RPC)
  - List of facilities in that city (from `facility` table) with surface type + court count
  - Embedded map (use existing `@rallia/shared-components` if there's a map component, else lazy-load `react-leaflet` or similar)
  - `SportsActivityLocation` JSON-LD for each facility
  - `ItemList` JSON-LD wrapping the facilities
  - At least 25-30% of content must be unique per page (real data, not templated) — the March 2026 core update aggressively demotes thin programmatic content
- [ ] City data file (`lib/cities.ts`) with name/slug/lat/lng/timezone
- [ ] Sitemap auto-includes from the city list × sport × locale
- [ ] Internal links from `/games` and `/communities` to relevant city pages
- [ ] Breadcrumb pattern: Home → Tennis → [City]

**Estimated effort:** 4-8 hrs (route + data layer + map + content shell)
**Why it matters:** captures long-tail local queries ("tennis Montréal", "pickleball courts Toronto"). Google Maps eats some of this intent but city-level reference pages are still net-positive, especially with the bilingual moat for QC cities.
